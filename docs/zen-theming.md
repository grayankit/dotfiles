# Zen Browser auto-theming

Zen's profile chrome is tracked as the `zen/` stow package
(`zen/.zen/wsnnxa2d.Default (release)/chrome/`) and deployed by
`scripts/setup.sh` (`stow zen`).

## How the colors flow

```
wallpaper change
  └─ dms/matugen regenerates ~/.config/DankMaterialShell/zen.css
       └─ chrome/dms.css (symlink) feeds it to:
            ├─ userChrome.css  → browser chrome (toolbar, sidebar, tabs)
            └─ userContent.css → internal about: pages
```

`custom.css` (hand-written) adds the personal touches: palette sidebar and
toolbox backgrounds (Zen's built-in `--zen-navigator-toolbox-background`
defaults to black), radii, and border cleanup.

## Reload rules (empirically verified 2026-10-05)

- **`userContent.css` (about: pages)** — re-read **per document**: open a new
  tab to see changes. No restart needed.
- **`userChrome.css` / `dms.css` / `custom.css` (chrome colors)** — loaded once
  at startup. **Restart Zen after a wallpaper change** to pick up the new
  palette. (Live-editing `zen.css` while Zen runs does nothing — tested.)

## Required prefs

| pref | value | notes |
|---|---|---|
| `toolkit.legacyUserProfileCustomizations.stylesheets` | `true` | required for any userChrome/userContent loading; already set in this profile |
| `svg.context-properties.content.enabled` | `true` | **defaults to true** in Zen — no action needed |

## Housekeeping

- `chrome/zen-themes.css` is generated by Zen Mods ("DO NOT EDIT") and stays
  profile-side only (gitignored if it ever lands in the package).
- `chrome/zen-themes/<uuid>/` are installed mod sources and are tracked.
- The profile id `wsnnxa2d.Default (release)` is machine-specific; a fresh
  profile means re-running `stow zen` from a renamed package path.

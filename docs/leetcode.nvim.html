leetcode.nvim

A complete guide to solving LeetCode problems inside Neovim · github.com/kawre/leetcode.nvim

1. What is it?

leetcode.nvim is a Neovim plugin that lets you fetch, browse, solve, run, and submit LeetCode problems without ever leaving your editor. It ships a dashboard menu, formatted question descriptions, an interactive console for running code against test cases, profile statistics, and support for the daily & random questions.

2. Your installed setup

The plugin is already installed via lazy.nvim in config/.config/nvim/lua/custom/plugins/leetcode.lua: 

return {
  "kawre/leetcode.nvim",
  cmd = "Leet",                    -- lazy-loads on :Leet
  build = ":TSUpdate html",        -- keeps html parser for description formatting
  dependencies = {
    "nvim-lua/plenary.nvim",
    "MunifTanjim/nui.nvim",
    "nvim-telescope/telescope.nvim", -- your picker provider
  },
  opts = {
    lang = "cpp",                   -- default language
    plugins = { non_standalone = true },
  },
}

Key fact: non_standalone = true lets you open leetcode.nvim from a normal Neovim session even if you have other buffers open.

3. Launching

Two ways to start leetcode.nvim:

  • Inside any session: run :Leet — opens the dashboard menu. (Preferred with your setup.)
  • Standalone: start Neovim with the plugin’s argument — nvim leetcode.nvim.

Since the plugin is lazy-loaded with cmd = "Leet", it loads the first time you run the command.

4. Signing in (getting your cookie)

leetcode.nvim authenticates using the Cookie header from your browser session. On first launch it prompts you to paste a cookie; afterwards you can update it with :Leet cookie update.

  1. Log in to leetcode.com in your browser.
  2. Open DevTools (F12) → Network tab.
  3. Reload the page, then click any request to leetcode.com in the list.
  4. Under Headers → Request Headers, find the Cookie: header.
  5. Copy the full value and paste it into :Leet cookie update.

Copy from request headers, NOT the set-cookie response header.

The cookie expires — if you see a “Your cookie may have expired” error, grab a fresh one. This also happens when LeetCode is rate-limiting during contests. Brave users: see issue #160.

5. Dashboard & navigation

The :Leet menu is a focused dashboard. From it you can pick actions, read your profile stats, or jump into problems. Inside the dashboard:

  • q — toggle (close) the current panel
  • <CR> (Enter) — confirm / select

7. Filtering lists & random

list and random accept optional arguments. Divide values with <key>=<value>; stack multiple values of one key by separating them with a comma:

:Leet list      status=accepted,solved difficulty=easy
:Leet list      status=new difficulty=medium,hard
:Leet random    difficulty=hard tags=dynamic-programming
:Leet random    status=bug difficulty=medium tags=graph,depth-first-search
statusnew · accepted · not-accepted · solved · not-solved · bug
difficultyeasy · medium · hard
tagsany LeetCode topic, e.g. array, hash-table, graph …

8. In-editor keys

Console / results

  • 1, 2, … — switch between test cases
  • r — reset test cases
  • U — use a testcase
  • H / L — focus the testcases / result panel

Switching questions

Each question opens in its own tab. Use :Leet tabs to jump between them.

Example: customizing for Python + an injector

opts = {
  lang = "python3",
  injector = {
    ["python3"] = {
      imports = function(default_imports)
        vim.list_extend(default_imports, { "from .leetcode import *" })
        return default_imports
      end,
    },
  },
  console = { dir = "row" }, -- run result below instead of to the side
}

10. Tips & troubleshooting

  • “Cookie may have expired” — refresh your cookie with :Leet cookie update. During contests LeetCode often rate-limits; wait and retry.
  • No LSP completions? Some languages need extra setup (e.g. Rust — see issue #86). C++/clangd works out of the box with your setup.
  • Description not formatted — the html tree-sitter parser must be installed (it already is in your config).
  • Keep the cache fresh — run :Leet cache update if new problems don’t show up.
  • Quick iteration — solve, then :Leet run locally; only push to the server with :Leet submit.
